## 3. 这一轮最重要的改动：依赖不是"上一个阶段"

原来幂等键取的是"上一个阶段的产物"。这在 QC 回退时会出错：
**换掉一镜素材 → ASSETS 产物变了 → VOICE 的键也跟着变 → 配音重跑**（2 万毫秒白花，且音画可能错位）。

改成显式声明依赖：

```python
STAGE_INPUTS = {
    RESEARCH: (),
    SCRIPT: (RESEARCH,),
    STORYBOARD: (SCRIPT,),
    ASSETS: (STORYBOARD,),
    VOICE: (STORYBOARD,),      # ← 只依赖旁白，不依赖素材
    RENDER: (ASSETS, VOICE),
    QC: (RENDER, ASSETS, VOICE, STORYBOARD),
}
```

于是：**换素材 → ASSETS 的键变；VOICE 的键只由 STORYBOARD 决定 → 命中 → SKIPPED。**
这就是"精准重做"和"断点续跑"共用一套机制的全部秘密。

## 4. 质检怎么判（能自动判 vs 判不了）

| DoD | 能自动判吗 | 本阶段做法 |
|---|---|---|
| 45–90s | ✅ | `ffprobe` 实测时长，block |
| 无黑屏 | ✅ | `blackdetect`，block |
| 无静音/爆音 | ✅ | `silencedetect` + `volumedetect`；削波 block，偏轻 warn |
| 字幕存在且覆盖音频 | ✅ | 取 SRT 最后一条的**结束**时间与音频总长比，block |
| 镜头与旁白语义相关 | ❌ | **只做"能不能用"**：文件存在、可解码、不是纯色/黑图（灰度 stddev < 6 判死） |
| 「能发」的观感 | ❌ | 必须抽帧人看（M3 的教训） |

> **诚实的边界**：QC 不假装能判断"好不好看"。它只挡"技术上不能发"的片子，
> 把"语义相关性"留给 CLIP（M6 可选）和人评（M7 抽样）。

决策逻辑（**它是路由器，不是打分器**）：

```
有坏镜 && 没有结构性失败 && 轮次未用尽  → RETRY（只标那几镜）
否则有 block 失败                      → PARTIAL（写清原因）
否则                                   → DONE
```

## 5. 四个真实问题

### 问题 1：字幕"覆盖不到结尾"——取错了字段

- **现象**：真机 QC 报 `subtitle_covers_audio FAIL: srt 结束 39.79 vs 音频 46.96`，差 7.2s 正好一镜。
- **根因**：正则 `(\d{2}):(\d{2}):(\d{2}),(\d{3})\s*-->` 匹配的是**左侧开始时间**，我拿 `[-1]` 当结束时间用了。
- **修复**：正则改为 `-->\s*(...)`，取右侧。
- **教训**：**时间轴数据要明确"取开始还是结束"**，这种错会让 QC 误杀好片子，比不做检查更糟。

### 问题 2：测试里的静音音轨被 QC 判死

- **现象**：全链路测试集体从 `DONE` 变 `PARTIAL`。
- **根因**：`audio_level` 要求峰值在 [-6, -0.1]，而测试用 `silent` 兜底，峰值 -91dB → block。
- **修复**：拆成两条：`no_clipping`（≥ -0.05 才 block，这是真爆音）+ `audio_loud_enough`（< -30 只是 warn）。
- **教训**：**block 只留给"绝对不能发"的条件**。把"不理想"当"不合格"，会让系统在正常输入上大面积误判。

### 问题 3：QC 写的 PARTIAL 原因被上层覆盖

- **现象**：任务确实是 PARTIAL，但 `error` 是 `terminal at QC`。
- **根因**：`run_task` 在阶段返回终态后无条件 `q.finish(...)`，把 QC 已经写好的 `degraded_reason` 盖掉了。
- **修复**：先查任务是否已是终态，只有仍是 `RUNNING` 才补写。
- **教训**：和 M4 那次是同一个坑的第二次出现——**上层不要覆盖下层已经写好的结论**。

### 问题 4：我的测试期望又错了（QC 跑 2 次 vs 3 次）

- **现象**：断言 QC 产物 = 2，实际 3。
- **根因**：忘了"手动重启触发质检"本身也算一次：初检(1) + 触发检(2) + 回退后复检(3)。
- **教训**：写断言前先数清楚**这次操作序列里有几次执行**，不要凭直觉。
