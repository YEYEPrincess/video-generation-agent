## 4. 三个必须说清的口径问题

### 4.1 这组数字不是"内容质量评测"

Mock 模型对任何主题都返回同一份脚本 → **20 条成片完全一致**（时长全 45.0s、motion 全 6.03）。
所以它证明的是「流水线在 20 次运行下稳定」，不是「内容好」。
README 与报告里都写明了这一点，并把「接真模型重跑」列为待办。

### 4.2 每个时长都恰好 45.0s，是设计不是巧合

配音实测 43.3s，不足 45s 下限 → RENDER 用末镜定格 + 音轨补静音补到 45.0s（M3 的 D-19）。
20 条全部命中下限，说明**脚本字数偏短**（Mock 固定 222 字）。
真实模型下字数会浮动，这个补时逻辑才会被真正压到。

### 4.3 为什么要加 `motion_score`

因为 M3–M6 之间出过一个 bug：所有技术指标（黑帧/静音/时长/码率）全绿，画面却是静止的。
`motion_score` 是唯一能抓住"技术全绿但内容是死的"的指标，必须进评测。

## 6. 整个项目回顾

| 里程碑 | 产出 | 最有价值的一件事 |
|---|---|---|
| M0 | 骨架 + 42 测试 | 原子抢锁一行 SQL |
| M1 | 文本链路 | 模型写内容、代码算时长 |
| M2 | 素材 + 配音 | `edge_tts.save` 不建目录 → 首镜必静音 |
| M3 | 出片 | `-shortest` 把 45s 截成 42.9s |
| M4 | 可被杀 | at-least-once + 幂等 = 结果只算一次 |
| M5 | 质检 + 回退 | VOICE 只依赖 STORYBOARD，换素材不重跑配音 |
| M6 | i2v + 修复 | **zoompan 的 d=1 让推近一直是假的** |
| M7 | 评测 + 文档 | 技术指标全绿 ≠ 内容是活的 |

**五个最值得讲的 bug**（都能在面试里展开 3 分钟）：

1. 静音兜底建目录，掩盖了"第一镜必失败"的真因（M2）
2. `-shortest` 让成片静默掉到 42.9s，验收差 2 秒就是不合格（M3）
3. 上层用 `terminal at X` 覆盖了阶段级错误码（M4 / M5 各犯一次）
4. 幂等键取"上一个阶段"，导致换素材要重跑配音（M5 重构为 `STAGE_INPUTS`）
5. `zoompan d=1` → 推近从未生效，三个里程碑无人发现（M6）
