## 3. 关键设计决策

| # | 决策 | 理由 | 代价 |
|---|---|---|---|
| D-8 | **模型写内容，代码算时间** | 45s/90s 是算术问题，交给模型必然飘；代码算 `len/4.2`，模型只负责表达 | 模型无法主动"多写一点凑时长"，只能按字数约束写 |
| D-9 | 无 key 自动回落 `MockLLM` | 测试、CI、离线开发永远能跑；也让人可以先把链路跑通再接模型 | 容易误以为"已经跑通真模型"（已记 D-07） |
| D-10 | 客户端**不重试**，只归类错误 | 两层退避叠乘会放大延迟和成本；重试策略集中在 runner 一处 | 单次调用失败立刻抛出，依赖 runner 兜 |
| D-11 | SCRIPT 阶段内部**带反馈重试 1 次** | 把"太短/超长"的具体原因回灌给模型，比盲目重试有效 | 多一次模型调用（仅失败时） |
| D-12 | STORYBOARD **纯代码** | 切分有确定算法；模型只会引入方差，且要 7 次调用 | `visual_prompt` 质量差（见 §5 问题 3） |

## 5. 三个真实问题

### 问题 1：测试数据自己违反了字数约束

- **现象**：`test_script_retries_with_feedback` 里"合格样本"算出 31.2s，仍被判太短。
- **根因**：样本段落是 `"这是" + "很充实的一段口播内容" * 3` = 32 字 × 4 段 = 128 字 ≈ 30s，写测试时没算。
- **修复**：改成 ×5（52 字/段 → 50.4s）。
- **教训**：**测试数据也要按真实约束构造**，否则测的是"测试写错了"而不是代码。

### 问题 2：报错误导 —— "分段数 0"

- **现象**：模型返回 3 段 3 个字的碎片，报错说"分段数 0 不在 3–10"，完全指不到根因。
- **根因**：`len(text) < 4` 的过滤把三段全丢了，然后才做数量校验。
- **修复**：过滤后为空且原始有段落 → 抛专门错误「所有段落都短于 4 个字符，请写出完整句子而不是碎片」。
- **教训**：**错误信息要指向根因，不是指向症状**。这条在评测阶段会救命——20 条样本跑失败时，你只有日志。

### 问题 3（设计缺口）：`visual_prompt` 不是画面描述

- **现象**：生成的是「最近打开B站你会发现十年前的番剧，扁平插画，近景特写」——把旁白前 16 字直接当主体。
- **后果**：T2I 会画出"文字碎片"式画面，直接撞 DoD「镜头与旁白语义相关 ≥4/5」。
- **决策**：**不在 M1 硬修**。STORYBOARD 只决定"说什么、多长、几镜"；"怎么画"属于 ASSETS（本来就是 Agent 阶段）。
- **计划**：M2 在 ASSETS 里用**一次批量模型调用**把所有镜头重写成「主体 + 动作 + 场景 + 风格 + 构图」。已记 `docs/debt.md` D-06。
