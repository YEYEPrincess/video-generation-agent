## 1. 验收句与结果

> **验收句**：`ffmpeg` 产出一条能播、有声音、有字幕的 mp4，时长 45–90s。

```
final=DONE  elapsed=105.5s
video: duration=45.0s  size=2.6MB  1920x1080@30   has_audio=True
       black_segments=0  silence_segments=0  tail_silence=2.33s  peak_db=-2.4
```

**分阶段耗时**：

| 阶段 | 耗时 | 说明 |
|---|---:|---|
| RESEARCH / SCRIPT | 11 ms | MockLLM（真模型约 2–5 s） |
| STORYBOARD | 18 ms | 纯代码 |
| ASSETS | 3 161 ms | 6 张图并发 |
| VOICE | 23 607 ms | 6 段 edge-tts + 静音修剪 |
| **RENDER** | **78 000～99 000 ms** | 6 片 × 1080p 编码 + 字幕重编码 |

**渲染耗时拆解**：单镜 8.3s 编码约 6–7s（0.75× 实时），字幕烧录还要把整片重编码一遍。
这是 1080p 的固有成本，M7 评测会加 `draft` 模式（720p/24fps）跑量。

## 3. 核心设计决策

| # | 决策 | 理由 | 代价 |
|---|---|---|---|
| D-18 | **时间轴以音频为准**，画面时长 = 该镜实测配音时长 | 字幕由音频累加而来，只有这样才能音画字三方同步 | 画面不能按"美学节奏"自由裁 |
| D-19 | 音频不足 45s 时：**末镜定格 + 音轨补静音** | 保证不违反 DoD 下限 | 片尾有 1–2s 静帧（已归为 `tail_silence`） |
| D-20 | 所有 ffmpeg 命令在 work 目录用 ASCII 相对文件名 | Windows 中文路径 + 空格 + filter 冒号 = 转义玄学 | 需要先拷贝素材（几 MB） |
| D-21 | RENDER 只校验**结构性**（可解码/有音轨/大小），黑帧静音只 `warn` | 拦在这里等于整条任务没有产物；质量判定归 QC | 问题延后到 M5 暴露 |
| D-22 | 配音尾部静音在 TTS 层剪掉，补 0.25s 换气 | 不剪的话 6 段拼接后是 6 个 0.8s 空洞，听感像卡带 | 多一次 ffmpeg 重编码 |

## 4. 五个真实问题（全部来自实测，不是推演）

### 问题 1：`No such file or directory` —— 相对路径 × ffmpeg cwd

- **现象**：`Error opening input file artifacts\...\RENDER\work\img_00.png`
- **根因**：素材路径是相对 `artifacts/` 的，而 ffmpeg 以 `work` 为 cwd 运行，相对路径二次解析。
- **修复**：`work = prepare_workdir(...).resolve()`，所有输入用绝对路径；输出仍用相对名（避免中文路径进 filter）。
- **教训**：**cwd 是隐式参数**，凡是"我给的是相对路径、对方也用自己的 cwd"的组合，一定会踩。

### 问题 2：`ZeroDivisionError` —— 音频流的 `r_frame_rate=0/0`

- **现象**：渲染成功（99s 白跑一遍），最后一步 probe 崩了。
- **根因**：`ffprobe -of default=nw=1` 会把视频流和音频流拍平成 key=value，音频的 `r_frame_rate=0/0` 覆盖了视频的 `30/1`，除零。
- **修复**：只在 `numerator>0 and denominator>0` 时赋值。
- **教训**：**ffprobe 的平铺输出没有流边界**，多流文件必须自己维护状态或改用 `-of json`。

### 问题 3：`-shortest` 把 45.0s 截成 42.9s

- **现象**：音轨 43.3s、画面 45.0s，输出只有 42.9s，直接跌破 DoD 下限。
- **根因**：`-shortest` 取两者较短；而音频拼接后有 AAC 编码的边角损耗。
- **修复**：显式 `-t target` 控制成片时长；音轨用 `apad=whole_dur` 补齐；画面末镜多留 0.3s 余量。
- **教训**：**"差不多 45 秒"在验收里等于不合格**。时长要当成硬约束显式设置，不能靠容器自动决定。

### 问题 4：6 段静音 —— edge-tts 每段自带 0.8s 尾巴

- **现象**：`silencedetect` 报了 6 段，每段 0.78s，位置正好在镜头交界。
- **根因**：edge-tts 每段末尾有约 0.8s 静音，6 段拼起来就是 6 次"卡带"。
- **修复**：TTS 侧 `areverse,silenceremove,areverse,apad=0.25`，剪掉尾巴补 0.25s 换气。
- **教训**：**拼接类问题永远在边界上**。单段听着正常，拼起来就露馅。

### 问题 5（抽帧才发现）：画面里的旁白大字和字幕重复

- **现象**：占位图把旁白画成大字，字幕又烧了一遍，屏幕上同一句话出现两次，且字幕压在文字上。
- **根因**：占位图早期用旁白当"内容"填充画面（M2 的设计），到 M3 加字幕后变成重复。
- **修复**：占位图只保留编号 + PLACEHOLDER + 装饰线；字幕改 `BorderStyle=3` 半透明底框、`FontSize=20`、`MarginV=42`。
- **教训**：**自动检测只能发现"技术性缺陷"，观感问题必须抽帧人看**。这条以后要写进评测流程。
