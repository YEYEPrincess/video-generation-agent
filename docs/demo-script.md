# 90 秒演示脚本

> 目标：让面试官在 90 秒内记住三件事——**端到端出片、杀进程不丢、有数据**。
> 录制建议：1080p 录屏，终端字号 16+，鼠标不要乱晃。

| 时间 | 画面 | 操作 | 旁白（照读） |
|---|---|---|---|
| 0–8s | 控制台首页 | 输入「为什么年轻人开始重看老动画」，点生成 | 这不是一个聊天框，是一个任务。提交后立刻返回 task_id，HTTP 不等结果。 |
| 8–20s | 进度条 + trace 滚动 | 指着 `RESEARCH → SCRIPT` 的事件流 | 七阶段流水线：调研、脚本、分镜、素材、配音、渲染、质检。前三步在用模型做判断，后四步是确定性代码。 |
| 20–35s | 分镜卡片 | 展示每镜的旁白、时长、画面描述 | 每个分镜都有明确的时长和画面描述，这是后面音画同步的依据。 |
| 35–50s | **终端 `kill -9`** | 另开终端，`taskkill /F /PID <worker>` | 我现在把这个 worker 强杀。任务状态在库里，进程只是执行器。 |
| 50–65s | 进度条恢复 | 指 `lease` 与 `state_transition` 事件 | 45 秒内另一个 worker 接手，从断点继续。前面已完成的阶段一个都没重算。 |
| 65–80s | 成片播放 | 播放 10 秒，字幕与配音对得上 | 45 秒成片，字幕烧录、配音对齐、无黑帧无静音。 |
| 80–90s | 评测表 | 切到 README 指标表 | 20 条评测，成功率 X%，单条 Y 秒，画面运动量 Z。这是我改了三版的结果。 |

## 备用素材（网络/接口挂了时）

1. `dev_out/demo-*.mp4`：已渲染好的成片；
2. `eval/report.md`：评测数字，不依赖现场跑；
3. `scripts/chaos.py --all` 的终端输出截图（三种故障全 PASS）。

## 讲解优先级（时间不够就砍后两条）

1. **杀进程那一段**（唯一无法被别的候选人复制的镜头）
2. **成片本身**（证明不是 PPT）
3. 指标表（证明有实验纪律）
